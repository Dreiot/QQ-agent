# 会话计时与真实模型流式验证

日期：2026-10-24。本次延续[界面实时更新验收](visual-realtime-2026-10-24.md)，使用用户新配置的 `deepseek-flash`，真实模型请求累计上限为 10,000,000 tokens。

## 修复内容

1. 等待倒计时原来每 100 毫秒更新一次，计时回调稍晚就可能从 0.3 直接显示 0.1。这是显示采样问题，不能据此推断整个应用只有 10 FPS。改为一个共享的 `requestAnimationFrame` 循环，跟随浏览器绘制帧计算当前显示值；只有文字变化时才写入文本节点。
2. 倒计时和运行耗时使用单调时间推进，避免系统时间调整令正在显示的时间倒退。列表与详情共享相同截止时间。空闲、隐藏、到期、移除及离开页签时停止计时绘制；绘制不会发起网络查询。
3. 真实模型测试发现：流式推理能够在运行时显示，但运行器在重建工具调用或普通结束的 assistant 消息时遗漏了 `reasoning_content`，导致完成后推理消失，后续工具轮次也未收到它。修复后保留模型返回的完整推理，同时继续使用转换后的正文与工具调用；不把尚未完成的流式片段提前加入模型输入，也不重复拼接最终推理。

## 实测结果

真实模型通过生产 LLM 解析器、运行器、调度器、会话仓库、SSE 和内置浏览器执行。QQ 连接及群消息使用本地合成环境，发送动作没有发往真实 QQ 群。测试使用两轮工具调用完成有限组合计算，不需要搜索或文件操作。

| 检查 | 结果 |
| --- | --- |
| 修复前复现 251ms 剩余时间、计时回调延迟 | 显示 0.3 → 0.1，缺少 0.2 |
| 修复后同样时序 | 依次显示 0.3、0.2、0.1、0.0，随后等待调度 |
| 隔离浏览器中采样 80 次计时绘制 | 间隔中位数 13.3ms，P95 13.4ms，未出现超过 100ms 的间隔 |
| 真实模型运行中，17:05:40.948 | 页面已显示 1,951 字符推理，状态仍在运行 |
| 真实模型运行中，17:05:47.107 | 页面推理增长到 5,657 字符，状态仍在运行 |
| 真实模型会话结束，17:05:51.642 | 完整 7,317 字符推理保留在会话中 |
| 工具执行后的下一轮真实请求 | 携带相同的 7,317 字符推理；请求成功 |
| 完整执行 | `send_message` → `finish`，会话已回复、无错误 |
| 输出核验 | 回复 328230，与独立动态规划计算一致 |

上述 80 帧是本机隔离浏览器窗口的计时组件采样，不代表整个应用在所有设备上的固定帧率。浏览器实际绘制仍受设备负载与页签可见性影响；不会为了补齐漏过的数字而延长真实倒计时。

总计 **5 次真实 HTTP 请求、54,433 tokens**，包含首个短探测、发现缺陷的一次完整会话，以及修复后的一次完整会话。用量取模型最终返回的 `total_tokens`，包含缓存输入，约占授权上限的 **0.54433%**。测试请求另有次数、输入大小和输出上限。临时修改的等待时间与会话重试设置均已恢复。
