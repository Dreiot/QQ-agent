# 用基础节点搭建 #sl 示例

在「规则 → 模板」选择「基础节点组合示例」，或导入 [示例规则](../examples/management/sl-removal.json)。这是一个数据与连线示例，默认关闭，不选择任何真实群。

这份示例不使用“整条消息完全相同”“每日计数加一”“持续撤回窗口消息”等旧组合节点。

## 数据和执行分别组合

1. 消息文字解析输出文字及“只含文字”；文字与 `#sl` 用通用“比较”判断，再用“逻辑运算”组合条件。
2. 条件通过才读取成员资料。成员身份与 `member` 比较，通过后调用独立的踢出方法，再确认调用成功。
3. 将踢出时间格式化为日期，与群号和原因拼成状态键。通用“数值累加”对这个键增加 1；没有按日专用逻辑，日期只是键的一段。
4. 通用“时间偏移”算出触发时间加 5 秒。事件源交给“时间窗”，窗口只输出该时段的数据。
5. “逐项处理”每次输出一条事件。循环内的“读取字段”取出 message_id，再交给独立的“撤回消息”。把该方法换成记录说明、状态写入或其他操作即可复用同一个窗口。
6. 全部项处理结束后，用昵称、QQ、踢出时间及累加结果填充文字，再调用发送方法。

公告仍为：

`[成员昵称]（qq：[qq号]）于[踢出完成时间]被移出群聊！此人为今日第[计数]个因发送#sl被移出群聊的成员。`

## 规则行为

- `#sl `、` #sl`、文字加图片、提及或回复不匹配。
- 管理员、群主、自身消息不启动惩罚路径。踢出失败或临时变更身份而被跳过，不累加、不清理、不公告。
- 昵称在踢出前读取；日期和公告时间来自踢出完成时间。状态键包含群号和本机日期，账号、规则、群与日期分别隔离，正常重启保留。
- 窗口为 `[触发消息发送时间, 发送时间 + 5秒)`，包含触发消息，不含恰好第 5 秒的消息。踢出耗时不顺延窗口。窗口到期后，已进入窗口的队列仍会排空，随后才公告。
- 单项撤回失败时，本示例的循环选择“记录后继续”，失败项数会显示；不会声称全部撤回成功。

## 基础节点的范围

圆形端口控制执行，方形端口传数据。每项操作放在循环区域内；“当前项”不能接到循环外，外部使用已处理项数和失败项数。输入的“必填”允许填写或连线，“自动”和“已填”均无需额外连线。

事件源只观察本次账号实际收到的消息，不拉取未知历史。每次消息操作仍核对当前群和权限；依照 [OneBot 消息字段](https://github.com/botuniverse/onebot-11/blob/master/event/message.md) 取得 ID 与时间，再调用独立接口。模拟不执行真实 QQ 操作。

更多通用用途与执行边界见 [基础节点说明](management-primitives.md)。
