# 同一客户端的多 QQ 账号

顶部使用账号单选卡片切换正在查看的账号。当前卡片使用强调色，其他卡片保持中性色；小圆点单独表达实际连接状态。切换前等待当前设置保存完成，随后打开所选账号的页面；其他账号的后台继续运行。卡片可换行，不限制为三个账号，支持方向键及 Home / End。

「设置 → QQ 连接」和「管理」使用独立的账号连接开关卡片。开启表示启用连接，关闭表示断开；等待连接时有单独状态，不能将协议端原生在线误报为 QQA 已连接。已保存账号、发行包配置中的账号及原生检测结果按 QQ 去重。未绑定账号开启时，严格核对选定 QQ 并完成原有接入流程；需要密码或扫码时仍由用户完成。

主账号关闭仅停止其协议传输，主控制台及其他账号继续运行；关闭意愿会保留到下次启动。关闭当前子账号前先保存，完成后返回主账号。卡片开关均在服务端确认后更新，并显示保存反馈；不会因重新开启而恢复自动回复。

## 添加和独立设置

在「设置 → QQ 连接 → 账号接入」中，通过 SnowLuma 选择另一个桌面 QQ。未接入的进程会首次注入，已在线的账号直接配置连接。HTTP、WebSocket 及新工作区自身的连接均核对目标 QQ 后，账号加入顶部列表。

每个新增账号由独立 Node 工作进程运行，拥有自己的设置、消息、会话、记忆、用量、授权记录、用户插件、技能和运行缓存。新账号以主账号基础设置为初始值，之后独立保存，不导入聊天历史、记忆或第三方扩展。安全的本机背景图会复制为独立文件。

新增和重新启动的账号默认暂停自动响应；确认配置后，可在该账号页面恢复。顶部暂停按钮只影响当前 QQ，桌面托盘的暂停操作覆盖所有后台。关闭子账号连接会停止其 QQA 后台；暂停则继续接收并保留未读消息。

应用窗口行为、开机启动、控制台访问令牌和协议端进程由主客户端统一管理。工作区设置页会说明这些边界。停止共用的 SnowLuma 会断开相关账号；停止某个 QQA 账号工作进程不会关闭 SnowLuma，也不会退出桌面 QQ。

## 数据及请求隔离

现有主账号数据继续使用原目录。新增账号使用 `data/accounts/<工作区 UUID>/data/`，用户扩展和运行缓存放在同一工作区的独立目录。清单只保存 QQ 身份、工作区和恢复意愿；内部认证令牌不会发给浏览器或写入清单。

新增账号的请求、实时事件和面板资源固定到 `/accounts/<UUID>/…`。路由不依赖全局「当前账号」，因此旧页面的迟到请求仍只会访问原账号。主题缓存、自动保存租约和背景路径也按工作区区分。账号列表使用单独的元数据事件流，不接收其他账号的聊天、思考或日志内容。

主账号会持久绑定首次识别的真实 QQ。若连接意外变为其他 QQ，会暂停并显示身份不匹配；短暂断线不会重新认号或创建重复账号。

## 2026-10-25 验证

- 通过 QQA 界面，对第二个新 QQ 主进程首次接入 SnowLuma，随后切回第一个账号；两次都核对了实际 HTTP / WebSocket 身份，两个桌面 QQ 均保留在线。
- 加载多账号版本后，再通过 QQA 将第二个 QQ 加入独立工作区。实际验证主内核与第二个工作进程同时连接不同 QQ，双方的独立 HTTP / WebSocket 及工作区身份均正确。
- 通过顶部选择器进入第二个账号，在界面修改并恢复「显示视觉能力标记」。磁盘检查确认只写入第二个账号，主账号设置未变。
- 在主账号页面停止并重新启动第二个账号，核对第二个后台及接口分别停止、恢复，主账号始终保持连接。卡片升级后又实际验证关闭当前子账号会保存并返回主账号；管理窗口的保存后停止失败路径用隔离测试验证恢复原页面。
- 真实双子进程测试使用本机模拟 OneBot，验证相同群号和消息编号的数据、会话详情、设置、插件及实时事件不串号。模拟消息未发送到真实 QQ。
- 账号监督器、网关、元数据事件流、扩展目录、界面作用域及切换保存等定向检查通过。未宣称整个历史测试集全部通过。
- 补充启动时等待主账号身份清单保存完成的并发检查，账号监督器共 26 项通过。重置流程显式先关闭账号和协议资源，再清理主业务并备份；隔离测试验证等待停止、子账号备份内容及重复关闭幂等。原有统一生命周期也会在备份前关闭资源，此次属于关闭顺序加固。
- 连接卡片升级后，账号监督器 30 项、协议端管理 29 项、协议接入 33 项及卡片 UI / RPC 边界检查通过。隔离真实进程测试核对主传输真实断开及重连时，其他后台的 WebSocket 保持不变。NapCat 延后接入和 SnowLuma 均在 HTTP / WS 身份验证后交接工作区，启动另一个账号不提前覆盖主账号配置。

### 卡片升级后的真实双账号复核

2026-10-25，使用 SnowLuma v2.1.1 和两个已登录的桌面 QQ，通过实际 QQA 账号卡片重新接入两个工作区。已有管理认证仍有效，无需重新输入密码。本次记录独立保存于 `.qa-local/multi-account-cards-live-20261025/`。

| 实际界面操作 | 第一个账号 | 第二个账号 | 共享 SnowLuma |
| --- | --- | --- | --- |
| 两个连接开关开启 | 已连接，身份正确 | 已连接，身份正确 | 运行中 |
| 在第二个账号页面关闭第一个 | 传输确已关闭，主控制台仍可用 | 保持连接，HTTP / WS 身份正确 | 原进程保持运行 |

顶部卡片实际切换到第二个工作区后，设置页显示其独立 QQ 身份和连接地址；关闭当前第二个账号后回到主账号。分别订阅保留账号的独立实时事件，覆盖另一个账号关闭与恢复的过程：第二个账号监测约 64 秒、主账号监测约 83 秒，均未收到断线、未就绪或错误身份事件，事件流也未中断。四个阶段都另行读取 QQA 自身连接状态，并用只读 HTTP / WebSocket `get_login_info` 核对真实账号。

最终两个工作区均已连接且暂停自动回复。QQ 协议端自身仍在线不等于 QQA 仍在连接；关闭阶段以 QQA 传输断开或工作区接口停止为依据。未发送 QQ 消息。
