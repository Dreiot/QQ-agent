# 基础节点与组合规则

节点描述一项可复用操作，业务规则由数据与执行连线组成。关键词、时间长度、身份和计数周期属于用户配置，不应成为核心执行器中的专用分支。

| 基础能力 | 输入 | 输出 | 其他用途 |
| --- | --- | --- | --- |
| 比较 | 两个值、比较方式 | 真假值 | 比价格、姓名、状态或对象 |
| 逻辑运算 | 真假值 | 真假值 | 多条件组合、取反 |
| 数值运算 | 两个数值、运算方式 | 数值 | 单价乘数量、差值、上下限 |
| 时间偏移 | 时间、偏移秒数 | 时间 | 任意到期时间、提醒时间 |
| 筛选列表 | 列表、字段、比较值 | 新列表、数量 | 筛选名单、记录、任务 |
| 提取列表字段 | 列表、字段路径 | 值列表 | 对象列表转 ID 或价格列表 |
| 事件源 | 群、事件类型、回看范围 | 持续事件流 | 记录、统计、通知、群管理 |
| 时间窗 | 事件流、起止时间 | 窗口内事件流 | 与任何逐项操作组合 |
| 逐项处理 | 列表或事件流 | 当前项、序号、汇总 | 对每条记录执行自定义分支 |
| 读取状态 | 键、缺省值 | 当前值 | 标记、缓存、流程上下文 |
| 写入状态 | 键、值、过期时间 | 新旧值 | 保存对象、文字、开关 |
| 数值累加 | 键、初值、增量 | 新旧值 | 分数、金额、任意周期计数 |

事件源只产生数据，不撤回、不统计，也不会自行结束。时间窗只限定数据范围，到期停止接收并排空已经进入窗口的数据；下游处理较慢时也不丢弃到期前的队列。逐项处理只负责把每项交给循环内的节点；具体操作由循环内的节点决定。

## 循环范围

“逐项处理”的“每项”出口连接循环内入口；“完成”出口连接列表处理完或事件流关闭后的步骤。在“每项”分支添加节点时自动归入该循环，也可在节点右侧选择执行范围。画布以虚线区域标示循环内容。

当前项与当前序号仅能在该循环内使用，不能直接接到循环外。循环外使用已处理数、失败数等汇总。每一项拥有独立计算缓存和上下文，支持最多 8 层嵌套；单项失败可停止或记录后继续。关闭规则、暂停或账号变化会取消等待与事件订阅。

## 状态键与周期

状态保存于当前账号的数据目录。可选择当前规则或当前账号范围；键完全由用户填写或拼接。例如：

- `群号 / 日期 / 移出原因`：按群、按日期计数。
- `用户号 / 周次`：每人每周积分。
- `订单号`：保存订单对象或金额。

不存在专门的“每日计数”逻辑：日期只是一个由“格式化时间”提供的键片段。数值累加是一次原子操作，多个轮次同时使用同一个键仍取得独立的新值。状态有 10000 个键、总计 8 MiB 的边界，支持过期及正常重启保留。模拟使用独立状态，不写入真实数据；可通过“预置状态（JSON，可选）”给模拟提供任意初始值。

## 兼容范围

以前保存的“整条消息完全相同”“每日计数加一”“持续撤回窗口消息”仍能读取与执行，避免破坏已有规则；它们不出现在默认节点库中。新示例使用基础比较、逻辑、状态、事件流、循环及独立的 QQ 方法，不使用这些旧组合节点。原先的“一轮每节点一次”现在限定在每个执行范围内，每次循环迭代重新计算其内部节点。

这不是完整的任意编程语言：不执行用户提供的 JavaScript，不允许跨越循环边界任意回连。现有其他快捷节点仍兼容；本次新增基础运算与控制是后续继续拆分的基础。
