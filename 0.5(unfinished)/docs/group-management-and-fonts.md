# 本机字体与规则编辑器

## 字体

在「设置 → 外观 → 精细调整 → 文字」分别选择正文、标题、代码字体。输入字体名称可筛选本机已安装的字体；留空恢复跟随默认样式。「点选元素」的字体输入框使用同一份列表，可以单独覆盖某个按钮、卡片或标题。

字体名称由运行 QQ-Agent 的电脑提供，只读取名称，不上传字体文件。新装字体后可点击旁边的刷新按钮。系统无法枚举时仍可手动输入名称，浏览器找不到字体会使用默认字体。

## 时间线

主导航的「规则」与会话、聊天、记忆、设置同级。规则、开关、群范围和执行记录属于当前 QQ 账号；切换账号后分别管理。设置中不再包含管理分区。

新规则默认关闭，所有修改自动保存并显示保存浮窗。可从空白规则开始，也可选择关键词管理、入群发言检查、多路分流、累计提醒、连续发言模板。规则名称、群范围与冷却设置收在「群聊」中，展开后才读取实际群身份，其他设置页不会提前查询所有群。

当前目录包含 109 种节点（含已有规则兼容项）（完整参数见 [节点目录](group-management-node-reference.md)）：

- 开始 11 种：消息、入群、离群、禁言、解禁、管理员变动、撤回、戳一戳、文件上传、入群申请、定时。
- 判断 26 种：关键词、文字长度、提及、连续发言、重复内容、日期星期、入群时间、名片昵称、用户数量、概率等。
- 分流 5 种：按消息内容、用户或身份选择分支，以及并行分发、按真假值分支。
- 选择对象 14 种：指定、全体普通成员、消息提及、排除、交集、身份、最近发言、随机抽取、名片、昵称、补充名单、清空目标等。
- 时间 6 种：等待、观察发言/未发言、等到指定时间、随机等待、冷却闸门。
- 计数 4 种：增加、判断、清空计次和自然日计数。
- 执行 16 种：禁言、解禁、踢出、群名、群名片、全员禁言/解禁、撤回、群消息、提醒、设置/取消管理员、专属头衔、同意/拒绝入群申请。
- 结束 3 种：记录说明、汇合点、结束。
- 查询 1 种：按 QQ 与群号读取成员资料。
- 数据 11 种：文字、数值、真假值、提取消息文字、读取字段、缺省值、拼接文字、数值比较、格式化时间、列表长度、填充文字模板。

默认使用横向节点画布，借鉴 [ComfyUI 的节点画布交互](https://support.comfy.org/articles/7675456845-the-comfyui-interface)，使用项目自身的界面组件实现。分支名只放在输出端口，连线不重复显示文字；节点分类用标题颜色区分。选中节点才展开参数，不常用的连接下拉框与说明默认折叠。

- 拖动标题自由摆放节点；位置随当前账号的规则自动保存，并包含在规则导出文件中。
- 从右侧输出圆点拖到左侧输入圆点连接；也可以依次点击输出和输入。拖线到空白处可直接选择后续节点，取消选择保留原连接。从输入端拖接只改接对应连线，循环连接会被拦住。同一输出最多连接 8 个后续节点，新增连线会保留原连接；输入端可汇合多路。
- 点击连线或右键输出端口，插入节点、选择已有节点或结束此分支。选中连线按 Delete 可断开；Esc 取消拖线，保留原有连接。
- 拖动空白处或用中键平移，滚轮以光标为中心缩放。双击空白处或点「＋ 节点」添加独立节点；新节点不会自动接到旧流程末尾。
- 「总览」显示全图，「整理」重新排布节点，「专注编辑」扩大工作区；列表视图保留键盘与下拉连接入口。默认按可读比例打开，长流程可平移查看。

插入节点会保留该分支后续步骤和其他分支原来的连接，已有节点位置保持不动；未接入节点会标出。画布拖动只刷新移动节点及关联曲线，平移和缩放只更新画布变换，松手后再保存位置，不按帧写入配置。

普通判断节点有「是 / 否」两条互斥分支。多路分流从上到下匹配，只执行第一条匹配分支；都不匹配走「其他」，每个分流节点最多 12 条条件分支。可嵌套分流，也可把多条路径连接到一个汇合点继续共同步骤。判断只启用一个出口，但该出口上的所有连接都会并行运行。汇合等待实际启用的路径，不等待未命中的分支，每轮每个节点只执行一次。循环目标不会出现在可选连接中，服务端仍会再次校验。

连线传递执行流程、触发事件和目标用户集合。分发时各路径复制目标集合、观察进度与模拟时间；汇合时目标用户去重取并集，观察进度取并集，模拟时钟取最晚时间，计次数值取各路最大值。实际计数器状态仍按规则与群/用户共享。每轮最多同时执行 8 个节点，有先后依赖的操作应串联。一路失败会取消本轮仍在等待的其他路径，已经被协议端接受的动作无法撤销。

节点库按用途细分分类，每个节点均有完整说明、输入、输出、例子与参数默认值。点击列表先预览，确认「添加到画布」后才创建；搜索同时支持用途、例子与旧名称。

增删、更换节点或调整连线后，规则会自动暂停，完成试运行再手动启用。参数调整继续自动保存。撤销、重做只恢复规则编辑，不会撤销已被协议端执行的真实操作；恢复业务配置的规则保持暂停。移动或整理节点、撤销与重做位置调整，只改变布局，不暂停规则或中断当前轮次。删除节点只结束指向它的连接，其他节点保留。

「消息匹配 / 消息不匹配」（原「发现 / 未发现」）支持文字包含、完全相同、开头、结尾、图片、视频、语音、文件、提及、回复、转发和网址。多个判断可串联，也可用不同的分支组合。

「用户未发送」必须有明确的观察对象和时间窗口。例如：成员入群 → 当前用户 → 60 秒内未发送 → 踢出群聊。可以观察任意一名选中用户，或要求每位选中用户都发言；后续观察只接收当前群内所选用户的消息。规则等待期间不会阻塞普通会话。

试运行的身份、成员和消息都是模拟输入，等待会快进，只显示预计操作，不调用真实群管理接口。关闭模拟窗口后，绿色连线显示经过的路径。可展开设置模拟时间、触发用户身份、名片、入群时长、预置计数、概率样本和消息类型。后续发言格式为每行「第几秒 QQ号 内容」，例如 `10 123456 我来了`；此前发言使用负数秒。模拟不写入真实计数和执行记录。

计次数按当前规则、群与触发用户（或整个群）分别保存，可跨轮次与正常重启保留。保留时长从最后一次增加开始计时，过期后归零。短时发言与重复内容使用独立的近期观察窗口，只在内存保存时间、用户与消息指纹，并限制每群 2000 条、总计 10000 条。消息指纹相同不等于文本语义相同；重复判断区分文字内容和媒体标识。

消息、名称、头衔与记录说明支持插入昵称、QQ、群号、次数、日期、时间变量，例如 `这是第 {{count}} 次提醒`。变量是普通文本替换，不执行表达式；替换后仍校验长度。群消息经过应用原有发送队列，真正出队时再次核验身份与取消信号。

## 独立字段与数据线

点击节点后，右侧分别显示数据输入、输出，包含中文名、字段名、类型及可选标记。支持查找字段；勾选框控制画布显示，已连接字段始终显示。消息节点提供发送者 QQ、群号、秒单位时间戳、文字、消息段、消息 ID、昵称、群名片、身份和原始事件等独立输出。非消息事件只展示对应事件支持的字段；缺失信息不会伪造。

执行端口为圆形，实线控制先后与分支。数据端口为方形，虚线按类型区分颜色；一条数据输出可连接多个输入，每个输入只有一个来源。拖动或依次点击方形端口连接，也可以在右侧直接选择来源。双击数据线或选中后按 Delete 断开；支持撤销、刷新保留、导入导出。不要把执行线接到数据端口。

例如选择模板「字段传值」：收到群消息的发送者昵称 → 拼接文字的后段文字 → 发送群消息的消息内容。另接执行线「收到群消息 → 发送群消息」控制发送时机。默认规则关闭，试运行后可看到各输出值的有界预览。

数据计算节点按需执行，同一轮只算一次，不需要执行线。读取成员资料等业务节点仍要有执行路径，数据线本身不会触发发送或群管理动作。输入留空时沿用当前流程的群、用户和目标列表；选择数据来源后，手动参数暂停使用，断开后恢复原值。单个操作用户与目标列表不能同时显式指定。

QQ、群号、消息 ID、文字、消息段、数值、时间戳、真假值和对象分别校验；任意值输出连接后还会按实际值再验一次。执行依赖与数据依赖一起禁止循环。动态参数同样受范围、长度和选项约束；动态群号必须在本规则选定范围内。

数据仅限本轮。未执行的业务节点不会提供上次的值；缺失字段会明确报错，可显式接「缺省值」处理。实时执行记录不自动保存消息全文、原始事件或字段快照；若主动把消息文字接到「记录说明」，该说明按配置写入记录。试运行只在返回结果中提供截断预览，不写入真实执行历史。定时节点的触发间隔是启动配置，仍通过手动参数设置。数据输入只覆盖当前节点；要继续传给后面的节点，请连接其数据输出。

## 实际执行与限制

普通成员也能运行事件、条件、计算、记录、状态、等待及回复规则。运行时和协议适配器仅在需要管理权限的具体操作前核验身份；权限不足时停止该轮后续执行并显示原因。禁言、踢出等会保护机器人自身、群主、管理员及身份未知的成员；「全体用户」只选普通成员。设置/取消管理员、专属头衔仅群主可执行；取消管理员可作用于管理员，仍不能更改机器人自身或群主。撤回前还会核对消息属于当前群。

同意/拒绝申请只能消费本轮实际收到的当前群申请标识，不会处理邀请机器人入群。机器人自己操作引起的管理通知不再次触发管理规则，避免禁言与解禁互相循环。协议端未明确确认成功，或不支持某项 API 时，记录会显示失败，后续节点停止。

停用、删除或修改规则、暂停当前账号、断开连接、更换协议实例或账号，会取消该规则仍在等待的轮次。停止前已被协议端接受的动作无法撤销。恢复运行或重启不会补跑停机期间的管理任务。定时节点从当前运行周期重新计时。暂停期间仍可编辑规则和试运行。

单条规则最多 200 节点、1600 条连接，每账号 100 规则，同时最多 32 个执行轮次；全体选择最多 1000 名成员。冷却时间按规则、群与触发用户分别计算；同一用户的上一轮等待未结束时，不重复启动同一规则。判断、等待和每次操作失败都会写入结果；节点错误停止当前分支，不继续执行后续动作。

执行记录通过实时事件更新，关闭记录面板时不连续请求记录。列表只获取摘要，展开某轮时才获取步骤详情；节点目录不会随每次实时更新重复下载。保留最近 100 轮于当前账号数据目录，界面展示最近 20 轮；磁盘写入合并处理。记录包含群号、用户号、节点结果，不记录触发消息全文或入群申请凭据。

## 扩展方式

默认组合组件为 `core.management`（运行时）、`console.management`（控制台接口）、`console.localFonts`（本机字体目录）。它们遵循现有可信 composition 的 replace/wrap 机制，不修改运行中模块的方法。

`createGroupManagement` 接受 `catalog` 与 `handlers`。自定义 catalog 项声明 `type / label / group / fields / branch / trigger`；自定义普通节点 handler 收到 `{node, groupId, event, targets, signal, dryRun}`，返回 `false` 走否分支，其他返回值走是分支。开始节点使用默认事件触发类型；额外平台事件需要在传输/触发适配层提供。参数只接受声明的有界字段，禁止执行用户提供的 JavaScript。

OneBot 的权限检查与 API 名称保留在 `bundled/transport-onebot/moderation.js`。其他协议适配器可实现 `getModerationMember / getModerationMembers / moderateGroup` 的同名平台无关契约。第三方普通技能不会因此获得任意管理动作权限。

## 基础运算与循环

见 [基础节点说明](management-primitives.md)。新规则可分别组合事件源、时间窗、逐项处理和独立方法；状态键由数据连线生成，周期不绑定在计数节点里。旧组合节点保留兼容，不显示在默认节点库。
