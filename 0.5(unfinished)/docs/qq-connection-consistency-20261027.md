# QQ 连接状态与接入一致性

本轮修复面向接入过程与真实连接不一致的问题，保留已有 QQ 的独立设置与数据，不修改发行包。

## 修复内容

- 已保存的 SnowLuma 账号重新连接时，重新进入原生接入流程；不会仅启动 QQA 工作进程后跳过原生接入。需要管理密码时明确显示验证入口。
- 原生已在线的 QQ 仍需核验 HTTP 与 WS 身份。端点证明失败时，刷新已注入的桥接，不重复加载 DLL；刷新前重新核对 PID 与 QQ。
- 复用已有端口和令牌时，再读一次原生配置，拒绝并发变更，不覆盖其他操作写入的新值。注册连接时，将所选 QQ 绑定到真实传输配置。
- 账号元数据保留收发通道是否就绪的判断，连接打开但身份或通道未就绪不显示已连接。重新配置时立即撤销旧成功状态，通过连接版本号拒绝迟到的旧端点状态。
- NapCat 自动和手动接入均区分“QQ 已登录”和“QQA 已连接”，工作进程尚未就绪时继续核验，不提前展示成功。
- 关闭协议端移出诊断折叠区，以危险色边框常显。关闭前说明所有关联 QQ 会断开，并允许取消。
- 移除未绑定真实 QQ 的“主账号”占位卡与界面用语。兼容内部工作区标识，不迁移或删除已有 QQ 的设置、历史。
- 手动地址默认镜像本账号实际使用的地址，更新不产生自动写回；手动修改、未保存草稿和正在编辑的输入不会被运行状态覆盖。令牌仍按账号保存与核对，明文只通过用户主动显示读取。

## 验证

自动验证包括：原生登录适配 31 项、登录控制器 44 项、账号工作区 37 项、协议端生命周期 43 项、实际 HTTP/WS 配置切换 48 项，以及地址同步与身份绑定的独立验证。浏览器覆盖常显关闭入口、停止确认与取消、已有 SnowLuma 账号不绕过注入、手填地址保护、空占位账号移除、扫码接入完整路径、账号切换及删除。

两个实际运行的隔离账号进程经过本机 HTTP/WS 认证验证了设置、消息、接口和停止操作的隔离；它们不是用户真实 QQ。首轮修复的证据与私有备份位于忽略的 `.qa-local/qq-connection-repair-20261027/`。用户完成管理密码验证后的真实 QQ 测试结果见下节。

SnowLuma 管理密码不新增持久化保存。重启后若原生连接需要重新接入且当前没有有效认证，界面需要用户验证密码；应用不能把未验证状态冒充为自动恢复成功。

### 复测中追加修复

- 未绑定 QQ 的内部工作区不展示虚假的运行/暂停控制；接入成功或首次载入发现已有连接时，由宿主核对真实账号后切入该账号，保留当前页签。已查看真实 QQ 时不会擅自切到另一个账号。该导航能力只允许内置连接设置调用，并拒绝旧页面迟到的请求。
- 新 QQ 进程可复用原来的地址和令牌；此时配置没有变化，旧重试退避可能让工作进程最多再等 30 秒，而接入流程只等待 8 秒。现在显式重新接入时，若配置相同但通道未就绪，会立即重连；已经就绪的连接不受打断，配置变化仍由传输层处理。新增回归覆盖上述三种边界，以及未核验时不能报告成功或恢复运行。
