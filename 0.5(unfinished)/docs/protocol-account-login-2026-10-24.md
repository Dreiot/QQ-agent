# 客户端内的协议端账号接入

QQ-Agent 作为应用层，通过用户自行安装的 NapCat / SnowLuma 管理接口提供账号接入窗口。项目和安装包仍不包含两家协议端的发行文件。

## 使用入口

「设置 → QQ 连接 → 本地协议端」启动发行包后，点击「账号接入」。

- **NapCat**：显示本地生成的二维码、扫码待确认状态和最终账号；支持手动刷新二维码。已登录的实例直接显示账号，不执行退出或重新扫码。
- **SnowLuma**：首次输入当前管理密码，然后从账号卡片选择桌面 QQ。未接入进程会注入，已经在线的账号会直接配置连接，不重复注入。支持动态验证码及恢复码。
- **手动运行的协议端**：点击「接入现有账号」。通过当前本机 OneBot 的 `get_version_info` 识别提供者，再由用户明确填写本机 WebUI 地址和管理密码；不会猜测管理端口。
- 首次协议确认、修改初始密码等步骤仍在协议端原生页面由用户完成，窗口提供原生页面入口。

## 状态与连接核对

NapCat 仅在账号窗口可见且登录尚未完成时刷新状态。二维码扫描内容在本机由 `qrcode@1.5.4` 转为 PNG，不将扫码 URL 用作远程图片地址。

SnowLuma 使用原生 SSE 推送通知，然后读取最新进程列表；流中断会退避重连，恢复帧到达后清除中断提示。隐藏时停止事件流及定时核验；关闭窗口或离开面板时再取消待处理请求。启动、窗口重开、配置变化均核对实例与会话身份，迟到结果不能覆盖新窗口。

接入 SnowLuma 时，先读取目标账号的完整配置，只合并 QQ-Agent 命名的 HTTP / WebSocket 节点，保留其他配置。每次为目标连接分配独立端口和随机令牌。提交 QQA 设置之前，分别通过实际 HTTP 和 WebSocket 的 `get_login_info` 校验两个端点确实对应所选账号；等待超过 30 秒会明确报错，不持续后台重试。

管理密码和原生认证会话仅留在宿主内存中，不写入 QQA 设置、日志或 SSE。托管 NapCat 可从本实例自己的 WebUI 配置读取访问令牌完成认证；不会读取浏览器登录存储，也不会尝试恢复 SnowLuma 的密码散列。

## 实现边界

- 新可替换组件 `runtime.protocolLogin` 在默认组合注册，通过构造注入配置、协议管理器、事件总线和网络实现，不修改协议端模块方法。
- 设置面板只能调用明确列出的接入操作。宿主重新核对原生页面的会话及本机地址，用户插件没有这些 API 权限。
- WebUI 接入仅接受明确的本机回环地址，禁用重定向，不提供任意地址代理。
- 本功能适配已验证的 NapCat v4.18.41 和 SnowLuma v2.1.1 API；上游变动可能需要更新适配器。

## 验证记录

原生适配 23 项、接入控制器 24 项及 WebSocket 核验 8 项检查均通过。它们覆盖原生认证、二维码编码、扫码中间状态、首次设置闸门、两步验证、进程身份变化、配置保留、HTTP/WS 错号拒绝、并发窗口、超时、SSE 重连及窗口清理。WebSocket 核验测试使用真实本机 HTTP Upgrade 和 OneBot 响应，未连接 QQ。

`protocol-login-roundtrip-test.mjs` 另外通过真实内核 HTTP、宿主 RPC 和设置页，连接本机模拟原生服务，完成二维码生成/解码/刷新及「等待扫码 → 已扫码 → 已连接」的完整链路。前端交互、现有协议管理器 26 项、设置权限、API 声明、SSE 链路和内核清理的定向回归也通过。没有运行或宣称整个历史测试集全部通过。

真实发行包验证：NapCat 已在 QQA 内显示实际登录账号及连接成功状态，未强制退出现有 QQ 登录。

2026-10-25，用户在 QQA 账号窗口输入当前 SnowLuma 管理密码后，真实认证通过，窗口显示桌面 QQ 的实际账号。分别向当前 OneBot HTTP 和 WebSocket 发送只读 `get_login_info`，两者均返回与可见账号一致的身份，QQA 的连接状态与协议管理器账号也一致。关闭并重开账号窗口后，仍显示相同账号，本次运行内无需再次输入密码。自动回复保持暂停，验证未发送 QQ 消息。

上述单账号验证当时没有执行首次注入和多账号切换。随后用户登录第二个桌面 QQ，2026-10-25 已通过 QQA 对其首次注入 SnowLuma，并切回原账号；两次均核对真实 HTTP / WebSocket 身份。升级多账号版本后，两个 QQ 由不同 QQA 工作进程同时连接，独立设置保存及第二个后台的停止、重启也通过实际界面验证。两者保持自动响应暂停，未发送 QQ 消息。详见 [同一客户端的多 QQ 账号](multi-account-2026-10-25.md)。真实二维码扫描与发行包检测的既有验证见 [发行包实测记录](local-protocol-real-validation-2026-10-24.md)。
